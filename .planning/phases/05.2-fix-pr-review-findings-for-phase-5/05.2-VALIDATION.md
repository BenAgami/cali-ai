# Phase 05.2: Validation Strategy

> This is the per-phase validation contract for feedback sampling during execution. Source: the `## Validation Architecture` section of `05.2-RESEARCH.md`.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4, two projects (`unit`, `integration`) in `apps/api`. `apps/native` and `packages/*` have no test runner. |
| **Config file** | `apps/api/vitest.config.ts` |
| **Quick run command** | `yarn workspace api test:unit` |
| **Full suite command** | `yarn workspace api test:unit && yarn workspace api test:integration` |
| **Estimated runtime** | Unit about 15 s; integration a few minutes (Postgres :5433 and Redis required). |

---

## Sampling Rate

- **After every task commit:** run `yarn workspace api test:unit` (or the targeted file) and `yarn check-types` for the touched workspace.
- **After every plan wave:** run all gates: `yarn format:check`, `yarn lint`, `yarn check-types`, `yarn knip`, `yarn workspace api test:unit`, `yarn workspace api test:integration`. Run the integration suite serialized, because the test database is shared. Rebuild `@repo/common` and `@repo/db` first if either changed.
- **Before `/gsd:verify-work`:** the full suite must be green.
- **Max feedback latency:** about 60 s for unit runs.
