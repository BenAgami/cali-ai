# Phase 5.2 Plan 07: Locked daily cap and capture resend status Summary

Concurrent captures can no longer exceed the daily cap: the count and insert run in one transaction behind a `FOR UPDATE` lock on the user row.

## Lock evidence

- RED: before the fix the concurrency test (14 seeded captures, 5 parallel submits) accepted all 5 (`[202,202,202,202,202]`) on 3 of 3 runs.
- After the fix: 5 consecutive runs of `-t "daily cap under concurrency"` all passed (exactly one 202, four 429 DAILY_ANALYSIS_LIMIT_REACHED, capture count equals the cap). `FOR UPDATE` shipped; the `pg_advisory_xact_lock` fallback was not needed.
