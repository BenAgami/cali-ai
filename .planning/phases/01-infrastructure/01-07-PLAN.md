<objective>
Expose the async capture pipeline over HTTP (INFRA-02): `POST /api/sessions/:id/capture` accepts gzipped keypoints, stores one `PoseCapture`, moves the session to PROCESSING/QUEUED, enqueues a `form-analysis` job and returns 202 + job ID without doing any analysis on the request thread. Add the retry endpoint (D-16) for FAILED sessions.

Resolved open question (RESEARCH Q4, retry endpoint shape): `POST /api/sessions/:id/analysis/retry`, no body, allowed only from FAILED, reuses the stored capture (no keypoint resend), resets stage to QUEUED, issues a NEW job id, returns 202 with the same response shape as capture.

Path note: the paths are `/api/sessions/...` exactly as written in ROADMAP criterion 1, CLAUDE.md and docs/architecture.md. They are served by a new `/sessions` router; the existing CRUD router stays at `/api/workout-sessions` (unchanged). Both address the same `WorkoutSession` id.

Purpose: The phone (Phase 5, and the 01-10 pipeline check) submits a set here; the worker (01-08) consumes the job.
Output: captureService, controller, router, size-cap middleware, OpenAPI paths, unit + integration tests.
</objective>

```typescript
const rejectOversizedBody = (maxBytes: number) => (req: Request, _res: Response, next: NextFunction): void => {
  const declared = Number(req.headers["content-length"]);
  if (Number.isFinite(declared) && declared > maxBytes) {
    next(new PayloadTooLargeError(`Request body exceeds ${maxBytes} bytes`));
    return;
  }
  next();
};
export default rejectOversizedBody;
```
Doc comment: checks the declared COMPRESSED size (D-04); the global `express.json({ limit: "10mb" })` in app.ts runs first and already bounds the inflated size (gzip-bomb protection), so this middleware enforces the tighter compressed cap without re-parsing.
