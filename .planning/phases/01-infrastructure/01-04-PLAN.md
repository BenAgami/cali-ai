<objective>
Decide MoveNet vs a 33-point model on real footage of the four core exercises (D-20, D-21, ROADMAP Phase 1 criterion 6). Claude builds an offline evaluator and the shot list; the developer films the clips; Claude runs the evaluation and records the decision.

Purpose: Phase 5 metrics and keypoint payloads depend on which skeleton (17 vs 33 points) the phone produces.
Output: `scripts/pose-eval/` evaluator, `results/summary.{csv,md}`, `01-POSE-MODEL-DECISION.md`, Key Decisions row.

Why offline: running all candidates on desktop over the same frames is faster and more controlled than three device builds. The 03 plan already proves MoveNet runs on-device; the winner's on-device integration is Phase 5 work. BlazePose has no official fast-tflite recipe (RESEARCH, LOW confidence) — if it wins, the decision file must flag that on-device integration risk.

Candidates (lightest first): MoveNet SinglePose Lightning int8 (17 kp) < MoveNet SinglePose Thunder int8 (17 kp) < MediaPipe Pose Landmarker Full (BlazePose, 33 kp).

Decision rule (D-21, thresholds are Claude's discretion): for each exercise, a model PASSES if, across that exercise's key joints, detection rate (confidence >= 0.3) is >= 90% AND mean confidence is >= 0.5, measured both over all frames and over the hard-position hold clip. The lightest model that passes all four exercises wins. If none passes all four, pick the model with the most passes (ties -> lighter) and record the failing exercise(s) as a Phase 5 risk. MoveNet uses keypoint score; BlazePose uses landmark `visibility` as its confidence.
</objective>

<interfaces>
Key joints per exercise (from RESEARCH Open Question 6), as joint names; the evaluator maps them to model indices:
- push_up: shoulders, elbows, wrists, hips, ankles
- pull_up: wrists, elbows, shoulders, nose (chin proxy)
- dip: shoulders, elbows, wrists, hips
- squat: hips, knees, ankles, shoulders
"shoulders" means both left and right (two joints), etc.

MoveNet (COCO 17) indices: nose 0, l_eye 1, r_eye 2, l_ear 3, r_ear 4, l_shoulder 5, r_shoulder 6, l_elbow 7, r_elbow 8, l_wrist 9, r_wrist 10, l_hip 11, r_hip 12, l_knee 13, r_knee 14, l_ankle 15, r_ankle 16. Output [1,1,17,3] as [y, x, score]. Lightning input 192x192, Thunder 256x256, uint8 RGB.
