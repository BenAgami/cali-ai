<objective>
Deliver job progress to the client over Server-Sent Events (INFRA-03): `GET /api/sessions/:id/status`, Bearer-authenticated (D-05), emits the persisted state first then live events from the Redis progress bus (D-09, D-10), closes on a terminal state, and keeps percent monotonic on the wire (D-07).

Purpose: The phone shows stage label + percent while waiting (D-15) and learns when the result is ready (ROADMAP criterion 3).
Output: SSE stream helper, controller + route, OpenAPI entry, unit tests (heartbeat/close/order), real-HTTP integration test.

Design notes:
- Subscribe FIRST, then read the DB snapshot, then emit (RESEARCH Pitfall 5): events published between the two steps are not lost; a stale DB snapshot that is lower than an already-sent live event is dropped by the monotonic filter; a terminal live event closes the stream so the later DB write is ignored.
- No event history and no Last-Event-ID replay (D-09): a reconnecting client simply gets the current state again.
- No compression middleware exists; do not add one (it would buffer the stream). `X-Accel-Buffering: no` defeats proxy buffering; 15 s heartbeats beat typical 60 s idle timeouts.
- Errors before headers are sent (404/409/401) go through the normal error handler; after headers are flushed, failures are logged and the stream is closed (the error handler cannot change a sent status).
</objective>

2. `controllers/session.ts` add:
```typescript
export const streamAnalysisStatus = async (req: Request, res: Response) => {
  const userUuid = requireUserUuid(req, res); if (!userUuid) return;
  const sessionId = Number(req.params.id);
  const session = await analysisStateService.findOwnedSession(userUuid, sessionId); // 404 before headers
  if (session.processingStatus === SessionStatus.PENDING) throw new ConflictError("No analysis has been started for this session");
  const stream = openSseStream(req, res);
  let lastPercent = -1;
  const emit = (event: AnalysisStatusEvent): void => {
    const terminal = event.status === "COMPLETED" || event.status === "FAILED";
    if (!terminal && event.progress_percent < lastPercent) return;
    lastPercent = Math.max(lastPercent, event.progress_percent);
    stream.send("status", event);
    if (terminal) stream.close();
  };
  const unsubscribe = await subscribeToAnalysisEvents(sessionId, emit);
  stream.onClose(() => { unsubscribe().catch((error: unknown) => logger.warn({ err: toError(error), sessionId }, "Failed to unsubscribe analysis stream")); });
  try {
    const current = await analysisStateService.getStatusEvent(sessionId);
    if (current) emit(current);
  } catch (error) {
    logger.error({ err: toError(error), sessionId }, "Failed to read analysis status for stream");
    stream.close();
  }
};
```
The single try/catch is the post-flush exception documented in the objective (the error handler cannot run once headers are sent); keep it to that block only. If `subscribeToAnalysisEvents` rejects after the stream opened, also log and close (wrap the subscribe call the same way).
