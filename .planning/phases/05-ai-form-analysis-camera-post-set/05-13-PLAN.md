  <behavior>
    evaluateSetup({ frames, exerciseCode, aspectRatio, lumaMean }):
    - fewer than 15 frames -> `{ isReady: false, issue: "NOT_DETECTED" }`
    - clean synthetic push-up side view, last 15 frames -> `{ isReady: true, issue: null }`
    - key joints visible in < 80% of the window and lumaMean 0.1 -> "TOO_DARK"; same with lumaMean 0.5 or null -> "NOT_DETECTED"
    - a key joint with x < 0.02 -> "CLIPPED_LEFT" (likewise RIGHT > 0.98, TOP y < 0.02, BOTTOM y > 0.98)
    - body bounding box spanning 0.3 of the frame -> "TOO_FAR"
    - push_up seen from the front -> "WRONG_ANGLE"; pull_up seen from the side -> "WRONG_ANGLE"
    - check order: detection, clipped, too far, wrong angle
    buildPoseCapturePayload(frames, meta):
    - timestamps rebased so the first is 0; result passes poseCapturePayloadSchema
    - more than CAPTURE_LIMITS.maxFrames frames -> truncated to maxFrames
    - fps = (n - 1) / lastTimestamp clamped to [5, 60]; durationSec <= 180
    - values are quantized (x has at most 3 decimals)
    - zero frames -> throws Error("No pose frames captured")
  </behavior>

    export const SETUP_ISSUES = ["NOT_DETECTED", "TOO_DARK", "CLIPPED_LEFT", "CLIPPED_RIGHT", "CLIPPED_TOP", "CLIPPED_BOTTOM", "TOO_FAR", "WRONG_ANGLE"] as const;
    export type SetupIssue = (typeof SETUP_ISSUES)[number];

    `useRecordedSet.ts`:
    ```ts
    export type RecordedSetPhase = "prerequisites" | "permission" | "setup" | "countdown" | "recording" | "uploading" | "uploadError" | "submitted";
    export const COUNTDOWN_SECS = 8; export const AUTO_STOP_SEC = 175; export const RECORDING_TARGET_FPS = 15;
    export const useRecordedSet = (params: { workoutId: number | null; setNumber: number | null; exerciseCode: FormAnalysisExercise; exerciseDisplayName: string; source: "execute" | "standalone"; onSubmitted: () => void }) => ({
      phase, missingPrerequisites, refetchPrerequisites,
      hasPermission, requestPermission, device, cameraPosition, toggleCamera,
      frameProcessor, isPoseReady,
      setupIssue, setupMessage, canStart, start,
      countdownSecondsLeft, isCountdownPaused,
      elapsedSec, stop, discard,
      uploadError, retryUpload,
    });
    ```
    Behaviour: phase starts at "prerequisites" when `getMissingAiPrerequisites` (from the profile, same derivation as useWorkoutGenerate) is non-empty, else "permission" until camera permission is granted, then "setup". The pose source `isActive` only in setup/countdown/recording (FORM-02: nothing runs before accept). Frames go into refs: a rolling 30-frame window for `evaluateSetup` (evaluated every 250 ms on a JS interval, not per frame) and, during recording, an append-only buffer capped at `CAPTURE_LIMITS.maxFrames`. `canStart` = ready continuously for >= 1000 ms. `start()` -> countdown of COUNTDOWN_SECS that pauses (`isCountdownPaused`) while not ready and resumes when ready; at 0 -> "recording" and the buffer resets. During recording update `elapsedSec` once per second; auto-call `stop()` at AUTO_STOP_SEC. `stop()` -> build payload with `buildPoseCapturePayload(buffer, { poseModelName, poseModelVersion, aspectRatio, cameraView: FORM_CAPTURE_SETUP[exerciseCode].cameraView, deviceModel, appVersion })` (deviceModel/appVersion from expo-constants/expo-device only if already installed; otherwise omit), keep it in a ref, then upload: create the session only if `sessionIdRef` is null (`sessionsApi.create({ exerciseCode, workoutId ?? undefined, setNumber ?? undefined })`), `sessionsApi.submitCapture`, `track({...})`, `if (source === "execute" && workoutId && setNumber) markRecordedSetDone({ workoutId, setNumber })`, phase "submitted", `onSubmitted()`. Errors: ApiError status 428 -> refetch profile, phase "prerequisites"; 429 with code DAILY_ANALYSIS_LIMIT_REACHED -> uploadError DAILY_LIMIT, 429 with code EXERCISE_ANALYSIS_LIMIT_REACHED -> uploadError EXERCISE_LIMIT; other -> uploadError UPLOAD_FAILED. `retryUpload()` reuses the payload and session refs. `discard()` clears refs without submitting. `useKeepAwake()` while phase is setup..uploading. Orientation: on mount `ScreenOrientation.lockAsync(OrientationLock.LANDSCAPE)` when `FORM_CAPTURE_SETUP[exerciseCode].orientation === "landscape"` (per the decision doc), and `lockAsync(OrientationLock.PORTRAIT_UP)` on unmount. Default camera position "front" so the user sees the framing guide; un-mirroring is handled inside the pose source.
