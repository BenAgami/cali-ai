export const createFakeLlmProvider = (steps: FakeStep[]) => {
  const queue = [...steps];

Service (`private get prisma()` pattern; default export singleton):
```ts
const DAY_MS = 24 * 60 * 60 * 1000;
type Attempt = { model: string; effort: LlmEffort; timeoutMs: number };
async generate(userUuid: string, input: GenerateWorkoutValues): Promise<WorkoutGenerationPreview>
```
Steps:
1. `userId = await getUserIdByUuid(this.prisma, userUuid)`; `context = await aiPrerequisitesService.assertAiPrerequisites(userId)`.
2. Cap: `count({ where: { userId, createdAt: { gte: new Date(Date.now() - DAY_MS) } } })`; `>= env.aiGeneration.dailyCap` → `new TooManyRequestsError("Daily AI workout limit reached. Try again tomorrow.", "DAILY_LIMIT_REACHED")`. Rolling 24 h; cap default 10 (D-18 discretion).
3. In-flight: `findFirst({ where: { userId, status: "PENDING", createdAt: { gte: new Date(Date.now() - env.aiGeneration.deadlineMs) } }, select: { id: true } })` → `new ConflictError("A workout is already being generated", "GENERATION_IN_PROGRESS")` (research Pitfall 4).
4. Catalog: `exercise.findMany({ where: { isActive: true }, select: { id, code, displayName, exerciseType }, orderBy: { code: "asc" } })`; empty → `ServiceUnavailableError("Exercise catalog is empty", "CATALOG_EMPTY")`. Build `Map` keyed by lowercase code.
5. `generation = workoutGeneration.create({ data: { userId, goalText: input.goalText, promptVersion: WORKOUT_PLAN_PROMPT_VERSION }, select: { id: true } })`; `log = logger.child({ generationId: generation.id, userId })`. Never log goalText (log its length only).
6. Ladder (D-16): `[{ primaryModel, primaryEffort, primaryTimeoutMs }, same again, { fallbackModel, fallbackEffort, fallbackTimeoutMs }]` from `env.llm`. One `AbortController` with `setTimeout(() => controller.abort(), env.aiGeneration.deadlineMs)` cleared in `finally`. For each attempt: `buildWorkoutPlanPrompt({ ...context, goalText, catalog, previousIssues })`, call `getLlmProvider().generateWorkoutPlan({ model, effort, maxTokens: env.llm.maxTokens, timeoutMs, signal: controller.signal, system, user, exerciseCodes })`. On `LlmError` REFUSAL / INVALID_OUTPUT / TIMEOUT: log warn `{ attempt, model, code }`, set `previousIssues` (for REFUSAL/INVALID_OUTPUT use `["The previous response was not a valid plan"]`), continue unless `controller.signal.aborted` (then stop and fail GENERATION_FAILED). On RATE_LIMITED / UNAVAILABLE: mark FAILED with `LLM_RATE_LIMITED` / `LLM_UNAVAILABLE`, throw `ServiceUnavailableError("The AI service is busy. Please try again shortly.", thatCode)`. On a result: `validateGeneratedPlan(result.plan, catalogMap, context.experienceLevel)`; ok → update row `{ status: "SUCCEEDED", model: result.model, attempts: n, completedAt: new Date() }`, log info with usage tokens, return `{ generationId, model: result.model, name, note, exercises }` (exercise summary `{ id, code, displayName, exerciseType }`). Not ok → `previousIssues = validation.issues`, continue.
7. Exhausted → update `{ status: "FAILED", attempts: 3, errorCode: "GENERATION_FAILED", completedAt }`, throw `ServiceUnavailableError("We couldn't generate a workout. Please try again.", "GENERATION_FAILED")`.
8. Any other error after the row exists → best-effort update FAILED `errorCode: "INTERNAL"` (catch and log a failure of that update with `{ err: toError(e) }`), then rethrow the original.
`getLlmProvider()` is called inside the try so a missing key becomes FAILED + LLM_UNAVAILABLE. Do not use `withTimeout`.
Tests: `vi.mock("../../../src/lib/llm", async (importOriginal) => ({ ...(await importOriginal()), getLlmProvider: vi.fn() }))` so the real `LlmError` class is kept; mock `aiPrerequisitesService` default; mock `../../../src/lib/logger` with a `child` returning `{ info, warn, error }` fns; `createPrismaMock()`; `vi.useFakeTimers()` + `vi.setSystemTime(new Date("2026-11-04T12:00:00Z"))` for the cap/in-flight Date assertions.
